头条：连"CLEAN"都是假的。spike-e 矩阵里 next 折进 turn 的 queued_command 在 transcript 无 banner，被当成"零 chrome 干净落地"——盲验用两条独立路径（让模型逐字复述它看到的第一行 + 二进制源码提取）证实：模型实收 midTurn 变体 wrapper（banner "while you were working" + 541 字安全段 + 回信尾巴），比 later 的包装还重。transcript 只是存储层假象。peer 消息不存在任何无包装 lane。
结论一："wrapped 去不掉"在模型可见层成立——模型无论如何都收到 wrapper。显示层（pane）的干净真实存在：next 折入渲染 ❯ 原文 与人打字同形（#102 前默认 next 时代人眼常见），但只在 next+忙+工具边界窗口出现，且折入消息执不执行是模型裁量（两轮实验 0/3 无视 vs 4/4 ACK，矛盾→无保证）。真实菜单：next = pane 常好看 + 响应靠裁量；later = pane 一定难看 + 必有一次响应。结论二：park 删除前提稳固，可开 PR（终态落地 byte-identical 双确认）。（后续：next 的裁量缺口已被出生协议的回执义务补上，hive 缺省翻转为 next——见 04。）

02边角硬发现（都有二进制/实测双源）

  • 帧内 priority 缺省或非法 → 默认 "next"，不是 "later"。claude_sessions.send() 始终显式携带 priority（当时是 "later"；缺省翻转后是 "next"），不依赖接收端缺省。
  • type:"human" 帧被接收端静默丢弃（无任何 transcript 记录）。
  • byte-exact 预包装 payload 触发幂等门（不二次包装），差一字节就双包——只防双包，去不掉 banner，且对 541 字常量逐字节敏感，跨版本脆弱，不是可用杠杆。
  • busy 排队期间，TUI pane 会以队列行显示裸 payload（"Press up to edit queued messages"）——人可编辑/删除。这是 park 与直发的唯一残余差异（过程态，非终态）。
  • 读 transcript 审计 peer 流量会系统性漏计 wrapper——模型可见层和存储层不同形，以后所有渲染类探针必须带 quoteback 或二进制交叉验证。

03对 hive 的直接后果

  1. park 删除 PR 解锁：前提"busy+later 直发与 park-to-idle 终态一字不差"被互盲双确认。删 parked.py + sidecar park/flush 分支，保留 later 直发。三防坑：显式 priority:"later"（已满足）；知悉 TUI 队列行的过程态差异；别拿 queuePriority 当 oracle。
  2. "wrapped 认了"的论证换了更硬的地基：不再依赖"CLEAN 不可靠"（K5 已推翻），而是"CLEAN 根本不存在"（K3 推翻）——模型无论如何都看到 banner+安全段，唯一无 banner 的 lane 是真键盘（origin.kind=human），peer 伪造会被改写回 peer。
  3. 安全段是功能不是噪音再获实证：now 路径的不执行案例全是模型引用安全段的显式拒绝——它真的在挡"peer 消息当 user 授权"。

04同日续篇：回执协议 + 实机验证 + 缺省翻转

K5 的"折入响应靠裁量"缺口被三臂实验定量收束（Haiku，每臂独立 fresh session，folded next 帧 mid-turn 注入）：

臂协议通道ACK 率要点
1无协议（基线）0/3折入消息 100% 可见（枚举探针 9/9 在上下文），但零响应义务 → 静默。
2聊天注入协议0/4模型把聊天里的回执指令判为 prompt injection，显式拒绝。
3CLAUDE.md 配置通道4/4合法配置通道立协议 → 全部回执。注入疑心只对聊天通道生效。

协议随即写进成员出生 skill（/hive:hive，PR #108）：两种 wrapper 变体二进制逐字入文 + SendMessage 纠偏 + 回执义务。scratch 队实机验证（nest 队，rex/probe 两真成员，claude 2.1.240/Haiku）：

  • A（later 途中到达）：收尾零静默处理全部消息，全程只用 hive reply/hive send——老指纹 SendMessage "no agent named" 消失。
  • B（raw next 折入）：pane 干净折入 ❯ <HIVE ...>，收尾主动回执（对照基线 0/3 静默）——回执义务经 skill 通道生效。
  • A2（member→member 回环）：hive reply probe --reply-to 3kIp 一次成功，对端实收。
缺省翻转：义务由协议扛住后，传输换回 clean 观感——claude_sessions.send() 的 priority 由 "later" 翻转为 "next"（本报告入库同一 PR）。mid-turn 折入 = pane 与人打字同形；idle 或无剩余工具边界 = 自起 turn。模型可见层永远 wrapped 不变。
