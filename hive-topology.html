Hive 协作拓扑 · 收敛总结

两种拓扑 · 一个原子 · 异族交叉审 — 2026-06-03
核心一句话：cell 是原子，crew 是 orch 套一层 + 按需挂 cell。
整套系统只有一个积木——「producer + 异族 cross-reviewer」——和一个「在它之上加个不写码的编排头」的算子。没有第三种东西。

拓扑一 · cell 原子 · 无 orch · 2 panes

        human  (你自己就是编排者，直连这对)
      派活 │ ▲ 汇报
           ▼ │
   ┌──────────┐   发现问题 → worker 认   ┌────────────┐
   │  worker  │ ───────────────────────► │ validator  │  异族 (codex)
   │  (doer)  │ ◄── code review + 接口测试 │            │
   └──────────┘                          └────────────┘
角色族职责写码
worker—实现（doer）✓
validator异族 (codex)代码 review + 接口测试✗ · 例外见下
  • 角色出生即定死：orch / 你永远知道把消息发给谁，不在「谁干谁审」上耗协商。
  • 固定身份、灵活下场：validator 抓到 bug、worker 认了 → validator 直接改更省事（省 bounce），但身份不变。
  • 无 orch：人就是编排者，直接和这对说话。

拓扑二 · crew 编排型 · orch + skeptic + 按需 cell

                      human
                批准  │ ▲  plan 上来给你过
              (闸2·人)▼ │
                ┌──────────┐
                │   orch   │   编排 / 拆 feature / dispatch，绝不写码
                └────┬─────┘
   plan ──► skeptic 审 (闸1·异族 agent) ──► human 批 (闸2) ──► 才 dispatch
                     │
          ┌──────────┴───────────┐   按需 spawn：每个 feature 一组，干完即 retire
          ▼                      ▼
     ┌ worker-cell ┐        ┌ worker-cell ┐   (并行就多挂几组)
     worker+validator       worker+validator
角色族职责写码生命周期
orch你的 pane编排 / 拆 feature / dispatch / 向人汇报✗常驻（= 跑 /hive 的那个 pane）
skeptic异族审 orch 的 plan（devil's advocate，闸1）✗常驻（crew 出生即 spawn 1 个）
worker—实现✓per-feature 临时
validator异族代码 review + 接口测试✗ · 同 cellper-feature 临时
  • 两道闸：orch 出的 plan 先过 闸1 = skeptic 异族交叉审，再过 闸2 = 人批准，才往下 dispatch。orch 不是单点。
  • board 已删（本轮已落地）：原 BLACKBOARD.md 是冗余第二通道。现在 —
    · live 状态 = window 名 <crew>-<id>-running/done/fail
    · durable 审计 = artifacts/verdicts/（survive cleanup）
    · features.json = planning 期 feature tree（执行期不更新，不是状态权威）
  • 同步走 hive 消息（send / reply / artifact），不靠共享文档。

贯穿两者的原则

1
原子 = producer + 异族 cross-reviewer。 cell 是它作用在「代码」上；crew 里 orch 产 plan、skeptic 审 plan，worker 产码、validator 审码 —— 同一动作，不同产出层。没有「裸 producer」。
2
异族强制（claude ↔ codex；droid→claude）。 每个 reviewer 一律与它审的 producer 不同 model-family，保证审视多样性。
3
角色出生即定，不协商。 落在 tmux @hive-role tag + 对应 role skill 上。寻址确定，省掉「谁干谁审」的来回。
4
不抢现有 pane。 orch = 跑 /hive 的当前 pane；skeptic = 1 个 spawn；worker/validator = 派 feature 时临时 spawn、干完回收。所以「现有散 agent 怎么分配 role」这个问题不存在 —— 谁想进自己 /hive 进来，不进的原样不动。
5
crew 概念已并入 crew。 曾设想的中间层「crew」= crew 去掉 board，既然 board 删了，crew 与 crew 合一，只留 crew 一个名字。
